```sql title="attach.sql"
-- duckdb -unsigned, then LOAD the extension; see Getting started.
ATTACH 'ducklake:moraine:s3://bucket/prefix' AS lake
  (DATA_PATH 's3://bucket/prefix-data/',
   -- Moraine records the data root in the catalog; same value as DATA_PATH.
   META_DATA_PATH 's3://bucket/prefix-data/', READ_WRITE);

CREATE TABLE lake.events (id BIGINT, payload VARCHAR);
INSERT INTO lake.events VALUES (1, 'hello, bucket');
```

[DuckLake](https://ducklake.select) currently stores table data as Parquet files
in object storage and keeps its catalog and inlined rows in a SQL database: a
DuckDB or SQLite file for one process; Postgres, or DuckDB served over
[Quack](https://duckdb.org/quack/), its new client-server protocol, for several.
Moraine is a DuckLake catalog backend that replaces the database with
[SlateDB](https://slatedb.io), a transactional key-value store whose state also
lives in object storage. The catalog sits in the bucket beside the data files,
and DuckLake's SQL runs against it unchanged.

## What you get

- **No catalog server:** Nothing to deploy, monitor, or back up. A deployment
  is a storage bucket.
- **Bucket durablilty:** A copy of the bucket taken while no writer is
  attached is a complete lake; see
  [Backups and copies](guide/operating/#backups-and-copies).
- **Nothing to pay for while idle:** An idle lake costs only storage, no
  compute or database hosting fees.
- **Indexed lookups:** Ordered indexes over table columns, maintained in the
  same commit as the rows, so a query by key probes the index instead of
  scanning every file; see
  [Index a column](guide/getting-started/#index-a-column).

## When not to use Moraine

- **For sub-5 ms commits:** A commit is durable once one write-ahead-log
  PUT lands: 50 to 100 ms on S3 Standard, 5 to 10 ms with the log on S3
  Express One Zone via
  [`WAL_PATH`](guide/configuration/#the-write-ahead-log-on-a-faster-bucket).
- **With many independent writers:** One process writes; the rest attach
  `READ_ONLY`. Concurrent commits go through that one writer. See
  [one writer, many readers](guide/getting-started/#one-writer-many-readers).
- **Not yet in DuckDB's community repository:** it loads with `-unsigned`, one
  build per DuckDB version.

## Status

Moraine is under active development and in production use at
[contour.app](https://contour.app). DuckLake SQL, including `CREATE`,
`INSERT`, `UPDATE`, `DELETE`, time travel, and maintenance, runs against
Moraine as its catalog and is validated against real DuckDB in CI. The
[roadmap](roadmap/) lists
what is done and what is next.
